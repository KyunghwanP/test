# 4시간 초과근무 관리 — 학교 계정 Apps Script

시간외근무 1일 4시간 제한이 풀리면서 필요해진 관리·감독을 **학교 계정이 소유한
스프레드시트**를 원본으로 처리한다. 앱(`overtime.html`, 앱의 '초과근무' 탭)은 이 시트에
붙은 스크립트와만 이야기한다.

- 다루는 것은 두 가지뿐이다: **기타 업무로 4시간을 넘길 예정이라는 허가**(승인·반려)와
  **자율학습 감독 배정·교체**. 시간 계산과 수당은 나이스가 한다.
- 신청 내용은 앱의 Firebase 에 두지 않는다. 감사 근거는 학교 계정 문서여야 한다.
- 시트는 전부 잠근다. 쓰는 것은 이 스크립트뿐이라 모든 변경이 「변경 이력」에 남는다.
- 누가 보냈는지는 앱 로그인 토큰을 구글에 물어 확인한다. 이름은 「교원 명렬」에서 채운다.

`Code.gs` 는 **배포본의 사본**이다. 고친 뒤에는 학교 계정의 Apps Script 에 다시
붙여 넣고 **새 버전으로 배포**해야 반영된다(아래 「고친 코드 반영하기」).

## 처음 설치 (학교 계정으로, 10~15분)

교무 공용 계정처럼 **평소 업무에 쓰지 않는 학교 계정**이 소유하는 것을 권한다.
시트 주인은 구글 시트 구조상 잠금을 풀 수 있기 때문이다.

1. 학교 계정으로 구글 드라이브 → 새로 만들기 → **Google 스프레드시트**.
   이름은 아무거나(예: `4시간 초과근무 관리대장`).
2. 시트 메뉴 **확장 프로그램 → Apps Script**. 프로젝트 이름을 `초과근무 관리` 로.
3. 편집기의 `Code.gs` 내용을 지우고, 이 폴더의 `Code.gs` 를 **통째로** 붙여 넣고 저장(Ctrl+S).
4. 왼쪽 톱니바퀴(프로젝트 설정)에서 **시간대가 (GMT+09:00) 서울**인지 확인.
   「편집기에 'appsscript.json' 매니페스트 파일 표시」를 켜고 이 폴더의
   `appsscript.json` 을 붙여 넣어도 된다.
5. 위쪽 함수 고르는 칸에서 **`setup`** → **실행**. 처음에는 권한을 묻는다:
   권한 검토 → 학교 계정 선택 → 허용. (스프레드시트, 외부 요청, 메일 보내기,
   트리거 권한을 묻는다. 외부 요청은 로그인 토큰을 구글에 확인하는 데만 쓴다.)
   실행 로그에 「준비됐습니다」가 뜨면 시트에 탭 일곱 개가 생긴다(숨김 탭 하나 더).
6. **「설정」 탭**에 적는다. 이메일이나 교원 명렬의 이름. 여럿이면 쉼표로.

   | 항목 | 적을 것 |
   |---|---|
   | 승인 (관리자) | 교감 |
   | 보기 (관리자) | 교장 (승인은 못 하고 보기만) |
   | 1·2·3학년 기획 담당 | 학년마다 감독 배정하는 분 (자기 학년만) |
   | 운영 담당 | `pkh910518@yeungnam.hs.kr` — 앱에서 명렬을 보내고 상태를 보는 사람 |
   | 메일 알림 | **시험하는 동안은 `끔`** 그대로. 실제로 쓸 때 `켬` |

   이름으로 적었는데 명렬에 없거나 동명이인이면 **권한이 가지 않는다**. 앱의 운영
   화면 「설치 상태」에 그 이름이 빨갛게 뜬다. 이메일로 적으면 확실하다.
7. **배포 → 새 배포** → 유형 선택(톱니) **웹 앱** →
   - 설명: `초과근무 v1`
   - 다음 사용자 인증 정보로 실행: **나** (학교 계정)
   - 액세스 권한이 있는 사용자: **모든 사용자**

   **배포** → 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사.
8. 앱의 **초과근무 탭**을 열면 연결 안내가 뜬다. 주소를 붙여 넣고 **연결 확인**
   (그 기기에서만 기억한다). **운영** 화면에서 **교원 명렬 보내기**를 한 번 누른다.
9. 주소를 알려 주시면 `overtime.html` 의 `OVERTIME_API` 에 넣어 커밋한다.
   그때부터는 기기마다 붙여 넣을 필요가 없다.
10. 시트 공유: 교감·교장에게 **보기 권한**으로. 담당자에게 공유할지는 정한다 —
    「② 기타 업무」에 선생님들의 업무 사유가 보인다. **편집 권한은 아무에게도 주지 않는다.**

### 「모든 사용자」가 고를 수 없을 때

학교 Workspace 관리자가 '조직 밖 공유'를 막아 두면 `yeungnam.hs.kr 내 모든 사용자`
까지만 나온다. 그 설정으로는 앱이 부를 수 없다 — 앱은 브라우저에서 바로 부르는데
그때 구글 로그인 쿠키가 같이 가지 않는다. 본인 확인은 '모든 사용자'로 열어 둔 채
**스크립트가 로그인 토큰으로 직접** 한다(토큰이 없거나 학교 계정이 아니면 아무것도
못 한다). Workspace 관리자에게 이 웹앱만 예외로 열어 달라고 하거나, 안 되면 알려
달라 — 그때는 다른 길(워커를 거치기 등)을 찾는다.

## 고친 코드 반영하기

붙여 넣고 저장한 뒤 **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**.
'새 배포'를 누르면 **주소가 바뀐다** — 앱이 옛 주소를 계속 부르게 되니 하지 않는다.

탭이나 설정 항목이 늘어난 판이면 `setup` 을 한 번 더 실행한다. 있는 탭과 적어 둔
값은 그대로 두고 빠진 것만 채운다.

## 탭

| 탭 | 내용 | 누가 쓰나 |
|---|---|---|
| ① 자율학습 감독 | 하루 한 줄. 학년마다 감독1·2·3(감독3 = 심야) 아홉 칸. 이름만 | 학년 기획 담당(배정), 교사(교체) |
| ② 기타 업무 | 4시간 초과 신청 — 근무일·구간·유형·사유·상태·처리자 | 교사(신청), 관리자(승인·반려) |
| ③ 통합조회 | 감독3(심야) + 승인된 기타 업무, 근무일 순. 맨 앞 칸이 월 | 스크립트가 매번 다시 만든다 |
| 교체·정정 | 교체 요청·긴급 교체·사후 정정·담당자 정정 한 줄씩 | 스크립트 |
| 변경 이력 | 모든 변경 — 시각·종류·대상·이전·이후·한 사람·비고 | 스크립트 |
| 설정 | 관리자·담당자 명단, 수락 기한, 메일 알림 | 학교 계정이 직접 |
| 교원 명렬 | 이름·부서·이메일 | 앱의 운영 화면에서 보냄 |
| 감독 상세 (숨김) | ①과 같은 모양 — 칸마다 이메일과 마지막 내력 | 스크립트 |

①에서 바뀐 칸은 색이 다르다 — 노랑 교체 · 빨강 긴급 교체 · 파랑 사후 정정 ·
보라 담당자 정정. 칸에 마우스를 올리면 「이전 → 이후 · 종류 · 시각」 메모가 보인다.
월별로 보려면 「데이터 → 필터 보기 만들기」(보기 권한으로도 된다).

## 규칙 (설계서 v0.8)

- **신청**: 오늘~60일 뒤 근무일. 구간(4~5·5~6·6~7·7~8·8시간 초과)·유형·사유(다섯 글자
  이상) 필수. 같은 날 대기·승인 건이 있으면 못 낸다. **고칠 수 없고 취소만**(근무일 전까지).
  오늘 근무를 오늘 내면 「당일 신청」으로 표시된다. 승인된 뒤 취소해도 승인 기록은 남는다.
- **반려**는 사유 필수. 관리자 본인 신청을 본인이 처리하면 이력에 「본인 신청」.
- **배정**: 학년 기획 담당이 자기 학년 세 칸만. 엑셀에서 날짜·감독1·감독2·감독3 네 열을
  붙여 넣고 미리보기 → 확정. 명렬에 없는 이름·동명이인·같은 사람 두 칸·그날 다른 학년에
  이미 있는 사람은 막는다. **이미 채워진 날짜는 덮지 않는다**(바꾸려면 정정).
- **교체**: A 요청 → B 수락하는 순간 바뀐다. 대신 서기 또는 맞교환(역할이 달라도 됨).
  **수락 기한은 근무일 당일 18:30**(맞교환이면 앞 날짜). 지나면 저절로 취소되고 A 에게 알린다.
  지난 날짜는 교체 못 한다. 누구든 그날 두 칸이 되면 막는다.
- **긴급 교체**: 못 나오는 A 가 앱을 못 쓸 때 대신 서는 B 가 등록 — **즉시** 바뀐다(사유 필수,
  그날 자정까지). 맞교환은 B 의 내일 이후 칸 중 **같은 역할**, **A 가 그날 비어 있는** 칸만.
  A·학년 담당·관리자에게 알린다.
- **사후 정정**(구두로 바꾸고 등록을 잊음): A 나 B 가 요청하고 상대가 확인해야 바뀐다.
  **근무한 달 말일까지**. 그 뒤로는 담당자·관리자 정정.
- **담당자·관리자 정정**: 담당자는 자기 학년, 승인 관리자는 어느 학년이든. 기한 없음, 사유 필수.
- 칸이 바뀌어 더는 이룰 수 없게 된 대기 요청은 **저절로 취소**되고 양쪽에 까닭과 함께 알린다.
- 15분마다 도는 시계(`tick`)가 기한 지난 요청을 닫고, **오후 4시**에 한 번 '오늘·내일
  근무인데 아직 처리 안 된 신청'을 승인 관리자에게 알린다.

## 보안에 대해

- 본인 확인: 앱이 보낸 Firebase 로그인 토큰을 `identitytoolkit accounts:lookup` 으로 확인한다
  (앱의 Cloudflare 워커들과 같은 방법). 학교 도메인·이메일 확인됨·정지 안 됨·학생 계정 아님.
  요청 본문의 이름·이메일은 쓰지 않는다. 확인 결과는 5분 캐시.
- 권한은 요청마다 「설정」 명단으로 다시 본다. 앱이 단추를 숨기는 것과 별개다.
- 앱으로는 **이메일이 내려가지 않는다**. 명렬의 사람은 이메일에서 만든 번호(id)로 고른다.
- `=`·`+`·`-`·`@` 로 시작하는 글은 시트가 수식으로 읽는다. 사유에 수식을 넣어 시트를 연
  사람의 화면에서 바깥으로 요청을 보내게 할 수 있어서, 앞에 빈칸을 붙여 글자로 넣는다.
- 한 번에 하나씩 처리한다(`LockService`). 메일은 시트에 다 적힌 뒤에만 나간다.
- 학교 계정이 시트에서 이름을 손으로 고치면 숨김 탭의 이메일은 옛 사람 것이 된다.
  그때는 명렬에서 이름으로 다시 찾는다(못 찾으면 그 칸은 교체가 막힌다 — 앱 감독표에 `?`).
- 웹 API 키(`FIREBASE_API_KEY`)는 앱에 이미 공개된 값이라 비밀이 아니다. 비밀값은 없다.

## 검사

```bash
node tests/overtime-gas.test.mjs     # 스크립트 단독 — 가짜 시트·메일·잠금·토큰 확인으로 모든 요청
node tests/overtime-page.test.mjs    # 화면 → 스크립트 (Chromium). 화면이 부르는 것을 진짜 Code.gs 가 답한다
node tests/overtime-tab.test.mjs     # 앱의 탭 배선 — 관리자에게만, 프레임은 한 번만
```

가짜 환경은 `tests/overtime-fake.mjs`. 칸 범위가 시트 밖이면 예외, 수식으로 읽힐 글을
쓰면 기록 — 실제 시트가 하는 것 중 이 스크립트가 기대는 것만 흉내 낸다.

## 막힐 때

| 증상 | 볼 것 |
|---|---|
| 「연결하지 못했습니다」 | 배포의 액세스가 '모든 사용자'인지. 주소가 `/exec` 로 끝나는지 |
| 「로그인을 확인하지 못했습니다」 | 앱을 새로 고친다(토큰 만료). 학교 계정으로 로그인했는지 |
| 「…탭이 없습니다」 | 편집기에서 `setup` 다시 실행 |
| 메일이 안 간다 | 「설정」의 메일 알림이 `켬` 인지. 하루 보낼 수 있는 수(학교 계정 기준 1,500명 안팎) |
| 시각이 어긋난다 | 스크립트는 날짜·시각을 서울 기준으로 직접 만든다(프로젝트 시간대와 상관없다). 그래도 어긋나면 알려 달라 |
| 권한이 안 생긴다 | 운영 화면 「설치 상태」의 '못 찾은 이름' — 이메일로 적기 |
