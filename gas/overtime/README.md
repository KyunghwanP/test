# 4시간 초과근무 관리 — 관리대장 시트 · 워커 · Apps Script

시간외근무 1일 4시간 제한이 풀리면서 필요해진 관리·감독을 **학교 계정(공용 계정)이 소유한
스프레드시트**를 원본으로 처리한다.

```
앱(overtime.html) ──→ 워커 overtime-api ──(구글 시트 API)──→ 관리대장 시트 (공용 계정 소유)
                          │                                   ↑ 처음 탭 만들기·잠그기 (setup)
                          └──(시트에 다 쓴 뒤)──→ Apps Script ─┘ 학교 메일 보내기
```

- 다루는 것은 두 가지뿐이다: **기타 업무로 4시간을 넘길 예정이라는 허가**(승인·반려)와
  **자율학습 감독 배정·교체**. 시간 계산과 수당은 나이스가 한다.
- 신청 내용은 앱의 Firebase 에 두지 않는다. 기록은 공용 계정 시트에만 남는다.
- 시트는 전부 잠근다. 쓰는 것은 워커뿐이라 모든 변경이 「변경 이력」에 남는다.
- 누가 보냈는지는 앱 로그인 토큰을 구글에 물어 확인한다. 이름은 「교원 명렬」에서 채운다.

처음에는 Apps Script 웹앱이 다 했는데 버튼 한 번에 1.5~3초(처음엔 4~6초)가 걸렸다.
그래서 시트 읽기·쓰기를 Cloudflare 워커로 옮겼다(보기 0.3~0.5초, 쓰기 0.5~1초).
**처리 규칙은 여전히 이 폴더의 `Code.gs` 하나**다 — 워커가 그것을 그대로 품고
(`node workers/build-overtime.mjs`), 시트 읽기·쓰기만 바꿔 끼운다. Apps Script 에 남은 일은
`setup`(탭 만들기·잠그기)과 학교 메일 보내기뿐이다.

## 처음 설치

### A. 관리대장 시트 — 공용 계정으로

교무 공용 계정처럼 **평소 업무에 쓰지 않는 학교 계정**이 소유하는 것을 권한다.
시트 주인은 구글 시트 구조상 잠금을 풀 수 있기 때문이다.

1. 공용 계정으로 구글 드라이브 → 새로 만들기 → **Google 스프레드시트**
   (예: `4시간 초과근무 관리대장`).
2. 시트 메뉴 **확장 프로그램 → Apps Script**. 프로젝트 이름 `초과근무 관리`.
3. `Code.gs` 내용을 지우고 이 폴더의 `Code.gs` 를 **통째로** 붙여 넣고 저장(Ctrl+S).
4. 함수 칸에서 **`setup`** → **실행** → 권한 검토 → 공용 계정 → 허용.
   「준비됐습니다」가 뜨면 탭 일곱 개(숨김 하나 더)가 생긴다.
5. **「설정」 탭**에 적는다(이메일이나 교원 명렬 이름, 여럿이면 쉼표).

   | 항목 | 적을 것 |
   |---|---|
   | 승인 (관리자) | 교감 |
   | 보기 (관리자) | 교장 (보기만) |
   | 1·2·3학년 기획 담당 | 학년마다 감독 배정하는 분 (자기 학년만) |
   | 운영 담당 | `pkh910518@yeungnam.hs.kr` — 앱에서 명렬을 보내고 상태를 보는 사람 |
   | 메일 알림 | **시험하는 동안은 `끔`**. 실제로 쓸 때 `켬` |

   이름으로 적었는데 명렬에 없거나 동명이인이면 **권한이 가지 않는다**(운영 화면
   「설치 상태」에 빨갛게 뜬다). 이메일로 적으면 확실하다.

### B. 워커 전용 구글 계정 — Firebase 콘솔에서

1. Firebase 콘솔 → 톱니바퀴 **프로젝트 설정 → 서비스 계정** → **새 비공개 키 생성** →
   JSON 파일을 받는다. 상담 예약 워커가 쓰는 그 계정이고, 키만 새로 받는 것이다.
   파일 안의 `client_email`(`…@ynhs-7b5ba.iam.gserviceaccount.com`)을 적어 둔다.
   **이 파일은 저장소·메신저에 올리지 않는다.**
2. 구글 시트 API 켜기 — 이 주소에서 **사용** 버튼:
   https://console.cloud.google.com/apis/library/sheets.googleapis.com?project=ynhs-7b5ba

### C. 시트를 워커에게 열어 주기 · 메일 중계 — 공용 계정 Apps Script

1. Apps Script 왼쪽 톱니바퀴 **프로젝트 설정 → 스크립트 속성 → 속성 추가** 두 개:
   - `WORKER_EMAIL` = B-1 의 `client_email`
   - `MAIL_SECRET` = 영문·숫자 아무거나 **32자 이상** (D 에서 똑같이 넣는다)
2. **`setup` 을 한 번 더 실행**. 「워커(…)가 시트를 쓰고, 이 스크립트는 메일만 보냅니다」가
   뜨면 된다. 워커 계정이 시트 편집자로 공유되고 잠금 예외에 들어가며, 이 스크립트의
   15분 시계는 꺼진다(시계는 워커가 돈다).
3. 웹앱 배포 — 처음이면 **배포 → 새 배포 → 웹 앱**(실행: 나, 액세스: **모든 사용자**),
   이미 배포했으면 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**.
   주소(`…/exec`)를 적어 둔다 — 메일 중계 주소다.

### D. 워커 — Cloudflare 대시보드

1. **Workers & Pages → 만들기 → Worker** → 이름 `overtime-api` → 배포 →
   **코드 편집** → 저장소의 `workers/overtime-api.js` 를 통째로 붙여 넣기 → **배포**.
2. **설정 → 변수 및 비밀** 에 넣는다.

   | 이름 | 종류 | 값 |
   |---|---|---|
   | `SA_JSON` | 비밀 | B-1 JSON 파일 내용 통째로 |
   | `SHEET_ID` | 텍스트 | 시트 주소 `…/d/` 와 `/edit` 사이 |
   | `MAILER_URL` | 텍스트 | C-3 의 `…/exec` 주소 |
   | `MAIL_SECRET` | 비밀 | C-1 과 같은 값 |
   | `ALLOWED_ORIGINS` | 텍스트 | `https://kyunghwanp.github.io` |

3. **설정 → 트리거 → 크론 트리거** 두 개: `*/15 * * * *`(기한 만료),
   `0 7 * * *`(한국 오후 4시 — 내일 근무 미처리 신청 알림).
4. 워커 주소(`https://overtime-api.○○○.workers.dev`)를 적어 둔다.

### E. 앱에 잇기

1. 앱의 **초과근무** 탭 → 연결 안내에 워커 주소를 붙여 넣고 **연결 확인**
   (그 기기에서만 기억한다).
2. **운영** 화면 → **교원 명렬 보내기**.
3. 워커 주소를 알려 주시면 `overtime.html` 의 `OVERTIME_API` 에 넣어 커밋한다.
4. 시트 공유: 교감·교장에게 **보기 권한**. 담당자에게 공유할지는 정한다 — 「② 기타 업무」에
   선생님들의 업무 사유가 보인다. 사람에게는 **편집 권한을 주지 않는다.**

## 고친 코드 반영하기

- **처리 규칙(`Code.gs`)을 고치면** `node workers/build-overtime.mjs` 로 `workers/overtime-api.js`
  를 다시 만들고, 그것을 워커에 붙여 넣어 배포한다. 검사(`overtime-worker.test.mjs`)가 빌드를
  잊으면 깨진다.
- Apps Script 쪽은 `setup`·메일 중계가 바뀐 판에서만 다시 붙여 넣는다 — 저장 뒤
  **배포 관리 → 수정 → 새 버전**. '새 배포'는 주소가 바뀌니 하지 않는다.
- 탭이나 설정 항목이 늘어난 판이면 `setup` 을 한 번 더 실행한다(있는 것은 그대로).

보라 담당자 정정. 칸에 마우스를 올리면 「이전 → 이후 · 종류 · 시각」 메모가 보인다.
월별로 보려면 「데이터 → 필터 보기 만들기」(보기 권한으로도 된다).

## 규칙 (설계서 v0.8)

- **신청**: 오늘~60일 뒤 근무일. 구간(4~5·5~6·6~7·7~8·8시간 초과)·유형·사유(다섯 글자
  이상) 필수. 같은 날 대기·승인 건이 있으면 못 낸다. **고칠 수 없고 취소만**(근무일 전까지).
  오늘 근무를 오늘 내면 「당일 신청」으로 표시된다. 승인된 뒤 취소해도 승인 기록은 남는다.
- **반려**는 사유 필수. 관리자 본인 신청을 본인이 처리하면 이력에 「본인 신청」.
- **배정**: 학년 기획 담당이 자기 학년 세 칸만. 엑셀에서 날짜·감독1·감독2·감독3 네 열을
  붙여 넣고 미리보기 → 확정. 명렬에 없는 이름·동명이인·같은 사람 두 칸·그날 다른 학년에
  이미 있는 사람은 막는다. **이미 채워진 날짜는 덮지 않는다**(바꾸려면 정정).
- **교체**: A 요청 → B 수락하는 순간 바뀐다. 대신 서기 또는 맞교환(역할이 달라도 됨).
  **수락 기한은 근무일 당일 18:30**(맞교환이면 앞 날짜). 지나면 저절로 취소되고 A 에게 알린다.
  지난 날짜는 교체 못 한다. 누구든 그날 두 칸이 되면 막는다.
- **긴급 교체**: 못 나오는 A 가 앱을 못 쓸 때 대신 서는 B 가 등록 — **즉시** 바뀐다(사유 필수,
  그날 자정까지). 맞교환은 B 의 내일 이후 칸 중 **같은 역할**, **A 가 그날 비어 있는** 칸만.
  A·학년 담당·관리자에게 알린다.
- **사후 정정**(구두로 바꾸고 등록을 잊음): A 나 B 가 요청하고 상대가 확인해야 바뀐다.
  **근무한 달 말일까지**. 그 뒤로는 담당자·관리자 정정.
- **담당자·관리자 정정**: 담당자는 자기 학년, 승인 관리자는 어느 학년이든. 기한 없음, 사유 필수.
- 칸이 바뀌어 더는 이룰 수 없게 된 대기 요청은 **저절로 취소**되고 양쪽에 까닭과 함께 알린다.
- 워커의 15분 크론이 기한 지난 요청을 닫고, **오후 4시** 크론이 '오늘·내일 근무인데 아직
  처리 안 된 신청'을 승인 관리자에게 알린다. 화면을 볼 때 기한이 지난 요청은 바로 '만료'로
  보이고, 시트에는 다음 쓰기나 크론 때 남는다(보기만 하는 요청은 시트를 쓰지 않는다).

## 보안에 대해

- 본인 확인: 앱이 보낸 Firebase 로그인 토큰을 `identitytoolkit accounts:lookup` 으로 확인한다
  (앱의 Cloudflare 워커들과 같은 방법). 학교 도메인·이메일 확인됨·정지 안 됨·학생 계정 아님.
  요청 본문의 이름·이메일은 쓰지 않는다.
- 권한은 요청마다 「설정」 명단으로 다시 본다. 앱이 단추를 숨기는 것과 별개다.
- 앱으로는 **이메일이 내려가지 않는다**. 명렬의 사람은 이메일에서 만든 번호(id)로 고른다.
- `=`·`+`·`-`·`@` 로 시작하는 글은 시트가 수식으로 읽는다. 사유에 수식을 넣어 시트를 연
  사람의 화면에서 바깥으로 요청을 보내게 할 수 있어서, 앞에 빈칸을 붙여 글자로 넣는다.
- 한 번에 하나씩 쓴다. 워커는 Firestore 의 잠금 문서 `locks/overtime` 하나로 줄을 세운다 —
  문서에는 '언제까지 잡고 있나' 만 있고 신청 내용은 없다. 잡은 워커가 죽어도 15초 뒤 풀린다.
- 쓰기는 요청 하나(`batchUpdate`)로 한꺼번에 — 전부 반영되거나 하나도 안 된다. 실패하면
  화면에 실패라고 뜨고 메일도 안 나간다. 메일은 시트에 다 적힌 뒤에만 나간다.
- 워커 전용 계정(서비스 계정)은 이 시트의 편집자이고, 상담 예약 워커와 같은 Firebase 계정이다.
  열쇠(JSON)는 Cloudflare 비밀값에만 둔다. 메일 중계는 `MAIL_SECRET` 이 맞아야 하고 학교 주소로만,
  한 번에 50통까지 보낸다.
- 워커로 옮긴 뒤(스크립트 속성 `MAIL_SECRET` 이 있으면) Apps Script 는 시트 요청을 받지 않고
  자기 시계도 끈다 — 둘이 같이 쓰면 서로의 잠금을 모른다.
- 학교 계정이 시트에서 이름을 손으로 고치면 숨김 탭의 이메일은 옛 사람 것이 된다.
  그때는 명렬에서 이름으로 다시 찾는다(못 찾으면 그 칸은 교체가 막힌다 — 앱 감독표에 `?`).
- 웹 API 키(`FIREBASE_API_KEY`)는 앱에 이미 공개된 값이라 비밀이 아니다.

## 검사

```bash
node tests/overtime-gas.test.mjs     # 규칙(Code.gs) 단독 — 가짜 시트·메일·잠금·토큰 확인으로 모든 요청
node tests/overtime-worker.test.mjs  # 워커 — 같은 일을 Apps Script 와 워커에 시켜 시트·응답·메일이 같은지 + 잠금·실패·크론
node tests/overtime-page.test.mjs    # 화면 → 규칙 (Chromium). 화면이 부르는 것을 진짜 Code.gs 가 답한다
node tests/overtime-tab.test.mjs     # 앱의 탭 배선 — 관리자에게만, 프레임은 한 번만
```

가짜 환경은 `tests/overtime-fake.mjs`. 칸 범위가 시트 밖이면 예외, 수식으로 읽힐 글을
쓰면 기록 — 실제 시트가 하는 것 중 이 스크립트가 기대는 것만 흉내 낸다.
