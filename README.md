# 영남고등학교 교사용 포털

교사·담임 업무를 한 곳에서 처리하는 웹앱과 그 주변 도구들. 시간표·학사일정·주간교육활동·
학생 종합검색·상벌점·성적·학부모 상담 예약·특별실 예약 등을 다룬다.

> 이 문서는 **구조와 운영 규칙**을 적어 둔 것이다. 기능 사용법이 아니라
> "어디를 고치면 무엇이 바뀌는가"와 "건드릴 때 주의할 점"이 목적이다.

---

## 1. 구성

| 구성요소 | 위치 | 역할 |
|---|---|---|
| **웹앱** | `index.html` 외 | 본체. 단일 HTML + Firebase(Auth·Firestore) |
| **서비스 워커** | `sw.js` | 캐시 전략 |
| **바탕화면 위젯** | `widget/ynhs-widget.ahk` | AutoHotkey v2 + WebView2 |
| **통합앱** | `app/ynhs-app.ahk` | 포털 창 + 위젯 토글. AHK + WebView2 |
| **데스크톱 앱** | `desktop/` | Rust(wry). 통합앱과 별개의 대안 |
| **상담 예약 API** | `workers/consult-api.js` | Cloudflare Worker |
| **자동화** | `.github/workflows/` | 성적·날씨·상벌점 동기화(test 전용), exe 빌드 |

배포는 GitHub Pages. **`KyunghwanP/ynhs` → `/ynhs/` 가 선생님들이 쓰는 실제 배포이고,
`KyunghwanP/test` → `/test/` 는 먼저 올려 보는 시험대다.** 두 저장소는 대부분 파일을
동일하게 유지한다(→ 6장 「두 저장소 동기화」).

## 2. 데이터 구조 (Firestore)

| 컬렉션 | 내용 | 쓰는 주체 |
|---|---|---|
| `appdata/main` | 시간표·교사 목록·내선·시정표 | `upload.html` |
| `appdata/operating` | 수업시수 운영표(요일 대체·창체·시험) | `upload.html` |
| `contacts/main` | 교원 연락망 | `upload.html` |
| `students/main` | 학생 명렬 | `upload.html` |
| `electives/{학년-반}` | 학생 선택과목 | `upload.html` |
| `gradesMock` `gradesSusi` `gradesIpgyeol` | 성적·입결 | Actions(서비스계정) |
| `acl/*` | 권한 관련 (아래 참조) | Actions + 관리자 |
| `consultations/{반}` | 학부모 상담 예약(개인정보 포함) | 교사 앱 · Worker |
| `consultationsPublic/{반}` | 위 문서의 **공개 미러** | 교사 앱 · Worker |
| `memos2/{uid}` `tasks/{uid}` | 개인 메모·업무 일정 | 본인만 |

### 교사 이메일이 다루기 까다로운 이유

`appdata/main.teachers`는 **시간표 엑셀에서** 만들어진다. 그래서

- 엑셀에 없는 `email`·`uid`는 **업로드할 때마다 사라진다** → 보존 코드가 `upload.html`에 있음
- **수업이 없는 교장·교감은 목록에 아예 없다** → 앱의 이메일 수집 대상이 되지 못함

그래서 이름→계정 해석은 **교원 명렬(`acl/emailByName`)을 1순위**로 쓴다. 로그인 여부·
시간표 등재 여부와 무관하게 전원이 들어 있다. 명렬은 `upload.html`의
**🪪 교원 명렬 업로드** 탭으로 넣는다.

## 3. 권한 모델

```
전체 열람(전교생 성적)  =  acl/gradeManual.managers 에 명시된 사람만
자기 반 열람           =  acl/gradeRoles.homerooms (담임, 자동)
관리자                 =  ADMIN_EMAIL (항상)
```

- **직위(교장·교감·부장) 자동 부여는 폐지했다.** 전교생 성적은 민감도가 높아
  "누가 권한을 갖는지 한 곳에서 눈에 보이는" 명시 명단 방식으로 운영한다.
- `acl/gradeManual`은 **보안 규칙이 직접 읽는다** → 콘솔에서 넣고 빼면 **즉시 반영**.
  동기화(Actions)를 기다릴 필요가 없다.
- `acl/*` 쓰기는 **관리자 계정만** 허용(`isAppAdmin`). 교사 전체에 열면 누구나 자기를
  전체열람 권한자로 넣을 수 있다.

### 관리자 '실제 권한으로 보기'

`admin.html`에서 교사를 고르면, Worker가 **관리자임을 검증한 뒤** 그 교사 명의의
커스텀 토큰을 발급하고 앱이 그 계정으로 로그인한다. 규칙이 **그 사람 기준으로 평가**되므로
권한이 제대로 부여됐는지 실제로 확인할 수 있다.

- 세션은 **메모리 전용 + 별도 Firebase 앱 인스턴스** → 관리자 본인 로그인이 유지된다
- 가장 상태에서는 **모든 쓰기를 차단**한다
- 자식 iframe(`grades.html`)에도 토큰을 전파한다 — 안 하면 그 화면만 관리자 자격으로 보인다

> ⚠️ 완전 가장이라 그 교사의 개인 메모·업무 일정도 열린다. 권한 점검 용도로만 쓸 것.

## 4. 학부모 상담 예약

```
[학부모]
  ├── 인증·예약·취소 ──→ Cloudflare Worker ──(서비스계정)──→ consultations/{반}
  └── 슬롯 목록 조회 ─────직접 읽기──────────────────────→ consultationsPublic/{반}
[교사 앱] ── 슬롯 편집 ──────────────────────────────────→ 두 문서를 한 트랜잭션으로 갱신
```

- 원본에는 예약자 이름·연락처가 들어 있어 학부모가 직접 읽을 수 없다. 그래서
  **개인정보를 뺀 미러**를 두고, 조회만 브라우저가 직접 한다 →
  **예약 오픈 시각의 접속 폭주가 서버에 닿지 않는다.**
- 선착순은 `updateTime` **선행조건**으로 처리한다. 잠금 없이 중복 예약이 막히고
  경합 시 재시도한다(GAS의 `LockService` 직렬화보다 정확하고 확장성이 좋다).
- 되돌리기: `parent.html`의 `USE_WORKER_DEFAULT`를 `false`로. 한 방문만 강제하려면
  `?worker=0`(GAS) / `?worker=1`(워커).

워커 배포·시크릿 설정은 `workers/README.md` 참조.

## 5. 배포와 자동 업데이트

| 대상 | 자동 반영 | 사용자가 할 일 |
|---|---|---|
| 웹앱 | ✅ GitHub Pages | 새로고침 |
| 통합앱(AHK) | ✅ 런처가 매 실행 시 최신 스크립트 수신 | 껐다 켜기 |
| 위젯(AHK) | ✅ 런처가 매 실행 시 최신 exe 수신 | 껐다 켜기 |
| **설치기·제거기** | ❌ | 새 패키지 받기 |
| **데스크톱 앱(Rust)** | ❌ | exe 교체 |

AHK 쪽은 **런처로 실행해야** 자동 갱신된다. `ynhs-widget.exe`를 직접 실행하면 갱신되지 않는다.

## 6. 건드릴 때 주의할 점

### WebView2 프로필 공유
통합앱과 위젯은 **같은 사용자 데이터 폴더**(`%AppData%\YnhsApp\Session`)를 써서
**로그인 상태를 공유**한다. 대신 제약이 생긴다.

- **브라우저 인자가 서로 완전히 같아야** 한다. 다르면 `0x8007139F`로 거부된다
  (한쪽만 구버전이어도 발생 → **둘 다 재시작** 필요)
- 넷로그 플래그는 `%AppData%\YnhsApp\netlog.on` **한 곳만** 쓴다
- 공유 실패 시 위젯은 전용 폴더로 물러난다(로그인은 따로 하게 되지만 동작은 함)
- **공유 중에는 프로세스 정리·프로필 삭제를 하지 않는다** — 같은 폴더를 쓰는
  `msedgewebview2`에 통합앱의 웹뷰가 포함되어, 위젯 문제를 앱 장애로 키운다

### 브라우저 인자
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`는 WebView2가 **브라우저 프로세스를 처음 띄울 때**
읽는다. 웹뷰를 만드는 시점에 설정하면 이미 떠 있는 프로세스를 재사용해 **무시된다.**
반드시 **스크립트 최상단**에서 설정할 것.

### 서비스 워커(`sw.js`)
- 화면(HTML)은 **네트워크 우선 + 3.5초 타임아웃** → 배포 직후 "반영 안 됨"이 없도록 신선도 우선
- 그 외 자원은 캐시 우선 + 배경 갱신
- **어떤 경로에서도 `undefined`를 반환하지 않는다**(→ `ERR_FAILED` 방지). 네트워크 대기에도
  상한을 둔다(무한 대기 시 워커가 요청을 붙잡아 `ERR_TIMED_OUT`이 난다)
- 캐시 저장소는 **경로가 아니라 출처 단위로 공유**된다. `/ynhs/`와 `/test/`가 같은 이름을 쓰면
  서로의 캐시를 지우므로, 캐시 이름에 배포 경로를 포함한다

### 두 저장소 동기화

**test에서 먼저 올려 보고, 확인되면 ynhs로 옮긴다.** 기본은 "양쪽을 같게"이고,
아래 세 부류만 예외다.

**① 배포 경로에 매인 값 — 옮길 때 반드시 `/test/` ↔ `/ynhs/` 로 바꾼다**

| 파일 | 바꿀 곳 |
|---|---|
| `manifest.json` | `start_url`, 아이콘 `src` |
| `index.html` | `REMOTE_BASE` (데스크톱 번들이 무거운 자산을 받아올 주소) |
| `widget/ynhs-widget.ahk` `widget/ynhs-widgets.ahk` `app/ynhs-app.ahk` | `APP_URL` · `APP_BASE` |
| `widget/ynhs-launcher.ahk` `app/ynhs-app-launcher.ahk` | 스크립트를 받아올 **저장소** 주소 |
| `widget/README.md` | 예시 주소 |

빠뜨리면 test 위젯이 ynhs를 띄우거나, 런처가 반대쪽 스크립트를 받아온다.

**② test 전용 — ynhs로 옮기지 않는다**

`admin.html`·`upload.html`·`scripts/`와 자동화 워크플로 5종
(`sync-grades`·`fetch-weather`·`scrape`·`riro-points`·`Summarize`).
스크립트는 **전부 Firestore에만 쓰고 저장소에 파일을 남기지 않으므로**, test에서 돌아도
ynhs 배포가 그대로 받는다. 양쪽에 두면 중복 실행이 된다.

**③ 그대로 두는 것**

- `sw.js` — 경로를 파일에 박지 않고 `self.location.pathname`에서 알아내므로 **양쪽이 같은 파일**
- `manual.html`의 주소 표기 — 선생님들이 실제로 쓰는 주소(`/ynhs/`)를 적는 게 맞다

> 옮긴 뒤에는 두 저장소를 파일 단위로 대조해 **경로 외 차이가 0줄**인지 확인할 것.
> 스쿼시 병합 후에는 브랜치를 `origin/main`에서 다시 시작해야 충돌이 나지 않는다.

## 7. 문제가 생겼을 때

| 증상 | 확인 |
|---|---|
| 성적 탭이 비어 있음 | `acl/gradeManual`·`acl/gradeRoles`에 그 이메일이 있는지 |
| 특정 교사만 권한 없음 | 교원 명렬(`acl/emailByName`)에 이름이 있는지, 표기가 같은지 |
| 위젯이 안 뜸 | 앱·위젯 모두 종료 + `msedgewebview2.exe` 전부 종료 후 재실행 |
| 위젯만 계속 실패 | 재시도 후 뜨는 "저장소 초기화" 안내를 수락 |
| 페이지 접속 자체가 안 됨 | 시크릿 창과 비교 → 되면 프로필 캐시 문제(`Clear site data`) |
| 자동화(성적·날씨)가 안 돎 | test 저장소 **루트에 `package.json`이 있는지**. `sync-grades`·`fetch-weather`는 루트에서 `npm init -y`를 하는데, 엉뚱한 파일이 있으면 JSON 파싱에서 죽는다 |
| 원인을 못 찾겠음 | **로그를 남길 것**: 브라우저 `net-export`, 위젯·앱 `netlog.on` |

마지막 항목이 중요하다. 증상만 보고 추론하면 헛짚기 쉽다. **실패하는 그 순간에**
로그를 캡처해야 DNS·TCP·TLS 어느 단계에서 무슨 오류로 끊겼는지 사실로 확인할 수 있다.
