# 테스트

이 폴더의 검사들은 **`index.html` 에서 실제 코드를 떼어내** 돌린다. 테스트 안에 로직을
다시 옮겨 적으면 원본이 바뀌어도 통과해 버려서, 검사가 아니라 장식이 된다.

### 편성표 업로드 (실제 편성표 파일 필요)

편성표 한 파일이 **명렬 · 선택과목 · 원본 파일** 세 곳을 갈아치우는 데다 되돌릴
수단이 없어서(시점 복구 불가), '돌아간다'가 아니라 **무엇이 저장되는지**를 값으로
확인한다. 같은 시트의 왼쪽(신원)이 명렬, `주소` 오른쪽이 과목이다.

```bash
PS_FILE=/경로/편성표.xlsx node tests/upload-pyeonseong.test.mjs        # 파싱·병합·막는 조건
PS_FILE=/경로/편성표.xlsx node tests/upload-pyeonseong-worker.test.mjs # 저장될 값으로 워커를 돌려 봄
PS_FILE=/경로/편성표.xlsx node tests/upload-pyeonseong-page.test.mjs   # 실제 화면에서 저장까지
```

파일이 없으면 조용히 건너뛴다(개인정보라 저장소에 안 둔다). 진짜 파일이 없을 때는
같은 지문(1020명 / 제외 55 / 343·322·355 / 앞 0 3건 / 번호 구멍 13반)을 재현한
대체 파일을 만들어 쓴다. 화면 검사가 쓰는 `prev-students.json` · `prev-contact.json`
(기존 DB 흉내)도 여기서 같이 나온다.

```bash
node tests/make-pyeonseong-fixture.mjs /tmp
PS_FILE=/tmp/pyeonseong.xlsx node tests/upload-pyeonseong-page.test.mjs
```

`upload-pyeonseong-worker` 는 `consult-api` 의 `handleVerify` 판정식과 `teacher-api` 의
`photoKey` 를 **워커 소스에서 그대로 떼어** 저장될 명렬에 돌린다. 학부모 인증이
전원 통과하는지, 사진 자리에 남의 얼굴이 붙지 않는지를 업로드 전에 값으로 본다.

화면 검사는 세 시나리오를 돈다 — 셋 다 저장 / 한 항목만 끄고 저장 / `주소` 열이
없는 학년이 있을 때. 마지막이 특히 중요하다: 못 읽은 학년은 저장 때 '이번에 없는 반'
으로 취급돼 **선택과목이 통째로 삭제**되므로, 그 항목만 잠기고 명렬은 그대로
저장돼야 한다.

### 운영표 업로드

```bash

```

머리 행(`교시 · 1학년 · 2학년 · 3학년`)을 찾는 부분을 본다. 예전에는 제목 줄에 빈 칸이
끼어 있거나(A1 제목 + H1 작성일) 표가 B열부터 시작하면 엑셀 행 배열의 구멍 때문에

있어도, 머리 칸을 띄어 써도(`교 시`) 읽어야 하고, 못 찾으면 파일 맨 위 몇 줄을 보여 준다.

### 교원 비상연락망 다시 올리기

```bash
node tests/upload-staff-contact-guard.test.mjs      # 편성표 파일 필요 없음
node tests/upload-student-contact-guard.test.mjs   # 학생 명렬 재업로드에 생일·번호가 안 지워지는가 + 백업 되돌리기
```

내려받은 파일에는 휴대폰이 **비어 있다** — 번호는 `contactsPhone` 에 있고 규칙이
브라우저 읽기를 막아 놓았다(워커만 읽는다). 그 파일을 고쳐 다시 올리면 저장이
통째로 덮어쓰기라 전 교직원의 번호가 한 번에 날아가고, 되돌릴 수단이 없다.

규칙(`contactsPhone` 읽기 = 관리자)을 올리고 나면 사람별로 합칠 수 있다 — 휴대폰
칸이 비면 저장된 번호를 그대로 두고, 적은 사람만 바꾼다. 지우려면 `-` 를 적는다.
아직 안 올렸을 때도 앱이 돌아가야 하므로 **양쪽 상태를 다 돌려 본다.** 규칙 전에는
번호를 못 읽어 병합이 안 되니, 명단의 `hasPhone` 으로 '몇 명이 지워지는지'를 세서
막고 `명단만 저장` 을 내준다.
저장은 통째로 갈아치우기라 **파일에 없는 사람은 명단에서 사라진다.** 퇴직·전출을
그렇게 처리하니 그 자체는 맞는 동작인데, '몇 명만 고쳐서 올리는' 경우와 파일만
봐서는 구분할 수 없다. 실제로 2명짜리 파일을 올려 30명이 2명이 됐다. 그래서
사라질 사람을 이름으로 보여 주고, 지울 때만 확인을 받는다.

검사는 실제 화면에 파일을 올려 저장까지 눌러 보고 **무엇이 저장됐는지를 값으로**
본다 — 막히는지, `명단만 저장` 이 `contactsPhone` 을 안 건드리는지, `hasPhone` 이
그대로인지, 번호가 든 원본은 예전처럼 둘 다 저장되는지, 일부만 든 파일이 확인
없이는 저장되지 않는지.

**퇴직 자리에 신규임용이 오는 경우**를 따로 본다. 그 행의 이름을 바꾸고 새 번호를
넣는 실제 상황인데, 여기서 절대 안 되는 것은 **퇴직자 번호가 신규자에게 붙는 것**
이다. 번호는 이름으로 찾으니 새 이름은 못 찾아야 정상이다. 번호를 깜빡하고 이름만
바꾼 경우에도 빈칸으로 남아야 한다.

### 생기부 보조자료 (saenggibu.html)

**생기부 작성**(학생별의 「✏️ 작성」 — 그 반 담임·관리자만): 오른쪽에 작성 칸(자율·진로·개세특·행특, 실시간 나이스 바이트, 쓰는 대로 저장)을
띄우고(보조자료와 반반), 그동안 보조자료 카드에 「→ 자율」 이 생겨 클릭으로 붙인다. 빼 둔 내용·학생 메모·되돌리기 기록(최근 10판), 행특 가리기(화면·인쇄),
이 학생/반 전체 컬러 인쇄(쪽 여백 0 — 브라우저 머리말·꼬리말 없이), 「📋 반 전체」(영역별 반 전체 표·복사·이름 누르면 그 학생).
검사는 담임 아닌 교사(단추 없음·읽기 없음), 담임(열기 전엔 안 읽음·자기 반 문서만), 다른 반 학생(단추·칸 없음), 다른 반 담임('3-02' 표기),
관리자, FHD 나란히·노트북(반·명단 접기)·폰(화면 가득·닫혀 있어도 붙이기)까지 본다. 규칙은 에뮬레이터 검사가 따로.

화면은 앱의 「학생 종합검색」 모양을 따른다 — 반 목록 | 명단(편성표 기준, 자료 건수, 학번이 어긋난 자료는 ⚠ — 번호 학생·같은 이름 학생 둘 다에 원 자료와 함께 보임) | 상세 세 칸, 같은 색·글꼴(Pretendard)·
크기. 학생 상세는 입력 영역별 묶음 + 문안마다 복사 + 「기재 문안 전체 복사」 + 참여한 활동 목록(활동명 + 입력 영역,
누르면 그 카드로 — FHD 에서는 카드 오른쪽에 붙어 따라오고, 좁으면 사진 옆 이름 아래). 한 칸에 회차가 줄바꿈으로 든
활동(프로젝트 봉사)은 줄 수가 같은 칸끼리 **회차 표**로 푼다. 위쪽 찾기는 학번(Enter)·이름(명단에서 걸러
읽기 없음). 폰에서는 단계식 — 학년 탭 + 반 격자 → 학생 큰 단추(2열) → 상세만 화면 가득, 위에 붙은
줄에서 ← 명단 · ◀ 이전 · 다음 ▶(담임이 반 학생을 차례로 넘겨 본다). 봉사 표도 폰에서는 회차마다 한 덩어리.
**봉사활동 누가기록**은 입력 영역에 '봉사' 가 든 누가기록 활동(봉사 시트·프로젝트 봉사 시트)을 칸 이름으로
맞춰 나이스와 같은 칸 차례(시작일자·종료일자·영역구분·봉사활동내용·학교/개인 구분·장소·시간·시간 누계)의
한 표로 합친다(모양은 앱의 다른 표 — 입력칸처럼 꾸미지 않는다) — 회차는 한 줄씩, 날짜 순, 칸을 누르면 그 값 복사.
「활동별로 나눠 보기」 로 원래 카드. 활동별 화면에서도 봉사 활동은 같은 표 — 맨 앞에 학번·이름, 시간 누계 칸은 없다(학생별 표에만). 기재 문안도 상자를 누르면 복사(글을 끌어 고르는 중이면 안 한다).
유의 사항은 상자 없이 굵은 주황 글씨 — 활동별·창체 일정·봉사 표는 두 줄, 학생별 카드는 한 줄까지 보이고
길면 「더보기」. PC 반 목록은 학년 단위로 접는다(처음엔 보는 학년만 펼침, 접은 것은 기억). 창체 일정은 자율·자치/진로/동아리로
거르고, 활동 내용이 빈 줄·소계 줄은 화면에서 뺀다(엑셀은 원본 그대로).

**반·번호·이름 확인**: 올릴 때 학교 명렬(`students/main`, 교사 읽기 가능)과 맞대 본다 — 이름이 다르면 그
이름이 명렬에서 실제로 어디 있는지(hint)까지, 명렬에 없는 학번도. 명렬이 없으면 시트끼리(같은 학번의 많은
쪽 이름). 결과는 `meta.mismatch` 에 남고 「⚠ 확인 필요」 탭(시트별)과 활동별 카드의 ⚠ 로 보인다.
편성표를 올릴 때 반·번호가 빈 학생(표 맨 아래의 전출·자퇴)을 `students/changed` 에 학년·이름·학적사항의
구분·날짜만 남긴다(생년월일·사유 글은 안 옮김 — 교사가 읽는 문서다). 명렬에 없는 학번이 그 학년 떠난 학생이고
그 이름이 학년에 더 없으면 「학적 변동」 — 확인 필요에서 빼고 회색 목록·명단 꼬리표로.

부서·교과가 모은 **기재 문안 통합 엑셀**(시트마다 활동 하나, 이름 앞 꼬리표 `<자>` `<진>` `<개>` `<누>`)을
관리자가 올리면 학생 하나 = 문서 하나, 활동 하나 × 학년 = 문서 하나(크면 조각)로 나눠 저장한다.
학생별 보기는 읽기 1번, 활동별 보기는 학년마다 1번. 자료가 계속 늘어나는 파일이라 반이나 학년을
문서 하나에 몰면 1MiB 한도에 걸린다.

**부서가 시트를 바로 올린다**(모든 교사, 규칙도 교사 전체 쓰기). 올라가 있는 것과 활동마다 맞대 보는데,
같은 활동인지는 시트 이름이 아니라 **차수를 뗀 이름**(`sgbActKey` — 꼬리표와 끝의 `-2차-3차(수정)` 을 뗌, 괄호 안 회차는 남김)으로
본다. 예전 합본에는 배포 차수가 붙어 있었고 앞으로는 안 붙이므로, 붙든 안 붙든·꼬리표를 고쳐 냈든 같은 활동이어야 겹치지 않는다.
새로 추가 · 바뀜 · 그대로 · 이 파일에 없는 기존 시트로 나눠 보이고, 교사는 늘 「추가·수정」(없는 시트는 그대로),
관리자만 「전체 바꾸기」(없는 시트 기본 지우기, 확인 창). 남(다른 교사)이 올린 활동을 바꾸려 하면 묻고 기본은 건너뛰기,
⊙ 활동명이 같은 짝 없는 기존 활동이 있으면 새 판인지 묻는다(기본 따로 추가). 쓰는 동안 `saenggibu/lock` 으로 잠그고,
잠근 뒤 목록이 미리보기 때와 같은지 다시 본다(학생 문서 하나에 여러 부서 문안이 함께 들어 있어 동시에 쓰면 한쪽이 지워진다).
남긴 시트의 줄은 저장된 활동 문서에서 다시 읽어 합치고, 하나라도 못 읽으면 아무것도 안 쓰고 멈춘다. 이름이 바뀐 짝은 목록 자리를
잇는다. 그다음 **바뀐 문서만** 쓴다(`saenggibu/manifest` 에 문서마다 지문), 누가 무엇을 했는지는 `saenggibu/log`.
검사의 가짜 Firestore 는 트랜잭션·지우기를 흉내 내고 쓴 경로를 남긴다 — 「바뀐 문서만 쓴다」 는 잠금·기록 문서를 빼고 센다(`dataOps`).

**관리 화면**(관리자만 보임): 잘못 올라간 활동을 통째로 지우고(같은 `sgbCommit`), 부서·활동명 등을 앱에서 바로 고친다 — 고친 값은
원본 칸과 따로 `fix` 에 둬서 부서가 같은 파일을 다시 올려도 남고, 화면·엑셀로 받기에 덮어 보인다(`sgbApplyFix`·`sgbFixForm`).

**추가·수정 꼬리표**(`sgbFresh`): 올린 지 7일은 모두에게, 그 뒤에는 안 본 선생님에게 볼 때까지(본 것은 브라우저에 기억).
본 것은 목록에서 직접 연 활동·학생 카드에 나온 활동 — 탭에 들어올 때 저절로 열리는 첫 활동은 아니다.

**머리 칸은 자리가 아니라 이름으로** 찾는다 — 부서마다 안내 줄을 더 넣거나 칸 이름을 바꿔 낸다.
같은 뜻의 이름을 한 표(`SGB_COLS` · `SGB_BODY_WORDS` · `SGB_SELF_WORDS` · `SGB_INFO`)에 모아 해석·양식 뜨기·
내려받기가 모두 그 표를 쓴다(따로 적으면 한쪽만 고쳐져 '읽기는 되는데 받으면 빈 칸' 이 된다). 반=학급,
번호=출석번호, 성명=학생명, 괄호 속은 덧붙임(`번호(출석)`), 기재 문안은 '기재 내용'·'특기사항'·'문안' 등
(여러 칸이 맞으면 센 이름 — `진로 특기사항 메모 | 기재 내용` 이면 기재 내용), ⊙ 안내는 '주의 사항'·'기재 영역' 등.
머리 줄은 위에서 40줄 안. **두 줄 머리**(병합)는 한 줄로 합친다 — 병합된 칸은 으뜸 칸에만 글자가 있어
그대로 두면 이름 없는 칸으로 버려지고 문안이 통째로 사라졌다. 머리 바로 위·아래의 메모·예시 줄을 칸
이름으로 착각하지 않게 겹침·학생 줄 여부를 본다. 그래도 놓치는 이름은 **올리기 미리보기**에서 잡는다 —
새로·바뀐 시트마다 어느 칸을 무엇으로 읽었는지 한 줄, 기재 문안 칸이 없거나 학생 줄을 못 읽었거나
표준 양식의 「예)」 예시 글이 남은 시트는 「⚠ 확인할 시트」(`sgbOddSheets`).

**표준 양식**(`tests/make-saenggibu-template.mjs`): 부서에 나눠 줄 빈 엑셀 — 작성 안내 + 활동 시트 둘(기본형,
칸을 더한 형). 모양은 원래 통합 엑셀(부서 이름 HY헤드라인M, ⊙ 안내 넷, 파란 머리줄, 숨긴 학번 열).
검사가 이 스크립트로 만들어 실제 파서·양식 뜨기로 읽어 본다 — 파서가 바뀌어 양식과 어긋나면 잡힌다.

**엑셀로 받기**(내부결재용): 목차 + 활동마다 시트 하나 + 창체 일정. 올릴 때 ExcelJS 로 시트마다 원본
양식(위쪽 안내 칸·병합·파란 머리줄·열 너비·숨긴 열·인쇄 설정·본문 칸 테두리)을 떠 `saenggibu/fmt-{id}`
에 두고, 받을 때 그 틀에 문안을 반·번호 순으로 다시 채운다. 본문 글꼴만 돋움 10 으로 맞춘다(여러 사람이
손대 섞여 있다). 줄 높이는 글자 수로 미리 잰다 — 실제 파일에서 원본 높이의 중간값 1.07배. 양식을 못 뜬
시트(서식 도구를 못 받았을 때 등)는 단순한 틀로 나간다. SheetJS 무료판은 서식을 못 써서 ExcelJS 를 같이 쓴다.
Playwright 의 Chromium 은 한글 다운로드 이름을 'download' 로 바꾸므로, 검사는 페이지가 붙인 이름을 따로 본다.

검사는 지어낸 엑셀로 실제 모양(⊙ 안내 칸, A열의 `00⊙`, 숨김 시트,
꼬리표 없는 조회 시트, 활동명이 복사돼 온 시트)을 흉내 낸다. 파일 이름은 영문으로 — Playwright 가
괄호·한글 섞인 이름은 조용히 못 넘긴다.

### 사용 현황 (usage.html · 🥚 빠른 메모 제목 5연타)

화면은 **`usage.html` 로 따로 뺐고, 앱 안에서 iframe 으로 띄운다**(자리 배치와 같은
방식). `index.html` 은 전 교사에게 내려가므로 거기 두면 관리자 혼자 보는 화면의
코드가 모두에게 실린다 — 여기에는 껍데기(iframe·돌아가기)만 둔다. 자료를 지키는 것은
여전히 규칙이다(`usage` 읽기 = 관리자) — 파일을 나눈 것은 굳이 안 내려보내려는
것이지 그것으로 막는 것이 아니다. `index.html` 에는 **세는 코드만** 남는다.


로그인 이벤트로는 사용량을 못 센다 — 세션이 유지돼 한 번 로그인하면 몇 달씩 다시
안 뜬다. 그래서 **앱을 연 횟수**와 **탭을 연 횟수**를 센다. 한 사람 한 달치가 문서
하나(`usage/{이메일}/m/{YYYY-MM}`)라, 잘못 쓰면 그 달 전체가 날아간다.

- 세는 게 맞는가 — 앱 열기·탭 이동·다시 열었을 때 이어지기
- 저장이 **그날 줄만** 건드리는가(merge), 탭마다 저장하지 않고 모아서 보내는가
- 관리자 말고는 못 들어가는가 — 다른 교사·보기 모드에서 5연타해도 안 열린다
- 전 교사에게 내려가는 파일에 화면 코드가 남아 있지 않은가
- **usage.html 이 실제로 뜨는가** — 가짜 Firestore를 물려 띄우고, 런타임 오류·집계·
  기능별 막대·옛 버전 표시·'모두 새로고침'을 값으로 본다
- 화면 집계가 맞는가 — 사람 수·횟수·날짜별 막대·기능 순위·안 쓴 사람
- **부르는 함수가 원본에 정말 있는가**

**전체 새로고침**도 여기서 본다. 배포해도 탭을 켜 둔 사람은 옛 화면을 계속 쓴다 —
서비스워커의 '새 버전' 안내는 화면을 새로 열 때만 뜨니 켜 둔 탭에는 영영 안 뜬다.
관리자가 `appNotice/reload` 의 번호를 올리면 열려 있는 화면들이 스냅샷으로 받는다.

- 처음 보는 기기는 번호만 적어 둔다(안 그러면 배포 순간 전원이 새로고침한다)
- 같은 번호가 다시 와도 아무 일 없다
- **묻지 않고 조용히 새로고침한다** — 막대도 카운트다운도 없다
- **보던 탭·스크롤로 돌아간다.** 기존 `restoreLastView` 는 시간표 안의 선택만
  되살리고 어떤 탭이었는지는 모른다 — 그대로 두면 현황판으로 튄다
- **적고 있으면 안 한다** — 그때만 막대를 띄우고 본인이 누를 때까지 기다린다
- 사람별 표에 지금 쓰는 버전이 뜨고, 옛 버전은 빨갛게 짚어 준다

'적는 중'은 넷 중 하나다 — 커서가 있는 입력칸에 글자가 있다 · 커서가 있는 편집
영역에 내용이 있다 · 모달이 열려 있다 · 화면에 보이는 `textarea` 중 내용이 있는
것이 하나라도 있다. 마지막이 중요하다. 적다가 다른 데를 클릭하면 커서가 빠지는데,
그때도 적던 내용은 살아 있어야 한다.

`location.reload` 는 덮어쓸 수 없어서(읽기 전용) 실제로 새로고침이 일어난다. 그래서
'몇 번 다시 받아 갔는지'를 라우트에서 센다. `setContent` 로 띄우면 localStorage 가
막힌 출처가 돼 저장 경로를 아예 못 보므로, 진짜 출처처럼 띄운다.

화면을 실제로 띄우는 검사가 왜 필요한가: index.html 에서 화면을 떼어 오면서 함수
밖에 있던 `let _usageBusy` 를 안 옮겼는데, 함수 호출을 훑는 정적 검사로는 변수
참조를 못 본다. 화면은 통째로 비고 콘솔에만 ReferenceError 가 떴다.

아래 항목은 하네스의 함정 때문에 넣었다. 하네스가 없는 함수를 대신 정의해 주면
원본에 없어도 검사는 통과한다. 실제로 그렇게 통과시켰다 — `esc()` 는 index.html 에
없고 `escapeHtml()` 이 맞는데, 하네스가 `esc` 를 정의해 버려서 화면이
'불러오는 중…' 에서 멈추는 걸 못 잡았다. 지금은 하네스가 원본에서 `escapeHtml` 을
떼어 오고, 이 구간이 부르는 이름이 원본(또는 import)에 있는지 따로 본다.

### 주간교육활동 그리기 (원본 대비)

세 가지가 있다 — `app`(지금까지) · `plain`(글꼴만 원본) · `orig`(Shadow DOM,
원본 + 스티키).

> **사이트를 통째로 iframe 으로 띄우는 것은 해 봤고 안 된다.** 구글이 삽입을 막아
> 둬서 빈 화면이 뜬다(2026-09 확인). 픽셀까지 같아지는 대신 스티키를 못 쓰는
> 맞바꿈이었는데 애초에 뜨질 않는다. 다시 넣지 않도록 검사로 못 박아 뒀다.

받아오는 것은 구글 사이트의 마크업이다. 앱이 그걸 고쳐 그리면 읽기는 편한데
원본과 디테일이 달라진다. 세 방식(`app` · `plain` · `orig`)을 놓고 고를 수 있게 해
뒀고, 검사는 **각 방식이 실제로 무엇을 바꾸는지**를 계산된 스타일로 잰다.

여기서 하나 확인됐다 — **앱이 힘으로 덮는 것은 글꼴 하나뿐이다.** 크기·색 규칙에는
`!important` 가 없어서, 사이트가 인라인으로 적어 준 값은 그대로 살아남는다.
'앱이 크기까지 다 덮는다'는 것은 사실이 아니었다.

검사는 **실제로 그리는 함수(`renderContent`)** 를 떼어 온다. 처음에 `renderWeeklyHtml`
에 붙였다가 화면이 안 바뀌어 한참 헤맸다 — 그 함수는 어디서도 부르지 않는 죽은
코드였다. '죽은 코드가 아니라 실제로 그리는 곳에 붙였는가' 를 검사로 못 박아 뒀다.

`orig` 는 Shadow DOM 이라 앱 CSS 가 아예 못 닿는다. 그 안에 넣는 것은 스티키
규칙 하나뿐이고, 바깥 상단 바 높이는 CSS 변수가 그림자 경계를 넘어 상속된다.

### 보안 규칙 (Firestore 에뮬레이터)

에뮬레이터를 먼저 띄운다. `firebase.json` 에 포트를 지정해 두고:

```bash
npx firebase emulators:start --only firestore    # 기본 8099 로 맞춰 둘 것
node tests/pass-rules.test.mjs                   # 외출증 규칙
node tests/saenggibu-draft-rules.test.mjs        # 생기부 작성(학생별 ✏️ 작성) — 그 반 담임·앱 관리자만(다른 반은 조회도 안 됨)
```

> 에뮬레이터가 거부된 쓰기마다 `evaluation error` 를 함께 찍는다. 규칙이
> `resource.data.…` 를 참조하는 거부 사례에서만 나오고 **결과는 항상 의도대로**다
> (거부는 거부, 허용은 허용). 원인을 끝까지 규명하지 못했으니 이 줄이 보인다고
> 규칙이 깨진 것으로 오해하지 말 것 — 판단은 통과/실패 집계로 한다.
